# Phase 295 — Evidence Envelope Self-Verification

## Contract

A `BacktestExecutionEvidence` instance now validates its own internal consistency at construction and through its public `verify()` method.

Verification checks immutable tuple dimensions, unique sorted symbols, dataset/provenance symbol agreement, row-count agreement, compatible provenance scope, the deterministic payload digest, and—when present—the strategy/configuration-derived execution fingerprint. A caller cannot use the public dataclass constructor or `dataclasses.replace()` to create an internally inconsistent evidence envelope without validation failing.

## Limits

Self-verification checks internal consistency of the supplied evidence object. It does not recreate the original candle bytes, authenticate the exchange, provide a digital signature, or prove the evidence was generated by trusted code. Persisted evidence should be protected by the application's trusted storage and audit controls.

## Verification

Adversarial tests mutate payload hashes, row counts, symbol identity, and execution fingerprints and require construction to fail. The existing valid envelope and deterministic fingerprint tests remain part of the runtime CI gate.
